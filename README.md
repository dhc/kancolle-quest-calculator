# 艦これ 定期任務 報酬計算器 v4（試作版）

## 現行版の変更点

- 集計期間は今月の月初から12か月。年選択は廃止。
- デイリーは週あたりの日数のみ指定。内部では固定の代表曜日を使って見積もる。旧個別曜日設定は日数を引き継ぐ。
- 達成率の設定は廃止し、旧設定の達成率は無視する。
- 周期・任務分類・検索条件を組み合わせ、表示中の任務を一括チェック／解除できる。前提任務の制約は維持する。
- 任務一覧の色帯で分類を識別できる。

## 使い方

`index.html` をChrome等で開くだけです。外部サーバー不要、ブラウザ内保存です。

1. 任務の「実施」をONにする。前提がある任務は上流を先にONにしてください。OFFの上流を持つ任務は選択できません。上流をOFFにすると後続もOFFになります。
2. デイリーは「週0〜7日」、曜日の個別指定はありません。
3. ウィークリーは「毎週（4〜5週）」、または「月1〜5週」を選び、「月初側／月末側」を指定する。
4. クォータリーは各期の実施月（1か月目＝3/6/9/12月、2か月目＝4/7/10/1月、3か月目＝5/8/11/2月）を選ぶ。
5. イヤーリーは任務の開始月を基準に、消化予定月を選ぶ。
6. 選択報酬・実施頻度を設定すると、指定月・月平均・年間の獲得見込みが更新されます。
7. 「ツリー順」をONにすると、前提と後続を近くに並べて表示します。任務の「前提を編集」から依存関係を追加・削除できます。
8. バックアップには「任務・設定をJSONで書き出す」を使用します。以前のv1で保存したデータは、同一ブラウザ・同一ファイルURLなど同じ保存領域で開けばv2・v3に移行を試みます。

## v4で追加した機能（報酬の詳細表示）

- **主要資材の4カード（ネジ・釘・バーナー・バケツ）は維持**し、画面上部の「資源・勲章・装備・その他報酬の集計を見る」を開くと、その他の報酬をカテゴリ別に表示します。
- 基本資源（燃料・弾薬・鋼材・ボーキ）は、従来の登録済み58任務について艦これWiki「資材」を参照して固定獲得量を追加しました。
- **追加アイテム**の記録対象は、勲章・戦果・改装素材・工廠資源・海外艦最新技術・補給アイテム・装備などです。各報酬を「アイテム名＋数値」で扱うため、任務マスターに登録されていれば年間・月間集計に含まれます。
- 任務一覧の「固定報酬」「年間の獲得見込み」では、従来の主要4資材だけを先に見せ、基本資源やその他報酬は行ごとの「基本資源・その他」を開いて確認できます。
- 保存した条件Aと条件Bの比較も、主要4資材だけを最初に表示し、**「資源・勲章・装備などの比較」**を開くと、その他報酬の年間・月間差分が見られます。月別比較の資材プルダウンでは装備などの名称を選ぶこともできます。
- 任務を手動追加する際、「追加報酬の登録」を開き、`燃料:200, 勲章:1, 試製 23号電探改三:1` のように追加できます。選択報酬も従来の `ネジ:2 | 釘:6` 形式で、装備名など任意のキーを扱えます。

### v3設定の移行

v3と同じ `localStorage` のキーを引き継ぎます。以前から保存済みの58任務には、今回の新規報酬のうち欠けているキーだけを補完し、任務ON/OFF、実施日・月、達成率、既存の選択報酬は保持します。v3の「吹雪改三」第1選択報酬についても選択内容を残し、第2選択報酬を追加します。保存済み比較条件も同様に補完します。

新たに取り込んだ任務データについては、`rewardCatalogVersion: 4` のあるものは報酬の自動補完を繰り返さない設計です。保存したデータを最終的に確実に引き継ぐには、作業後JSON書き出しによるバックアップをおすすめします。

### 報酬の計算上の注意

集計はすべて**受け取る報酬（グロス）**です。任務に必要な勲章・資源・装備の消費、海域出撃に使う資源、EO報酬、勲章交換などは収支に含まれません。装備名は文字列として扱うため、同一装備でも改修値が違えば別項目です。実施ONの任務は設定した頻度で達成するものとして計算します。

## v3で追加した機能

### デイリー・クォータリーの共通デフォルト

画面上部の「実施頻度の共通デフォルト」で、次の初期値を設定できます。

- **デイリー**：週0～7日。週3日なら、初期曜日は月・水・金です。
- **クォータリー**：各期の1・2・3か月目。四半期は3～5月、6～8月、9～11月、12～2月です。

これらは**新たに手動追加する任務の初期値**に使用します。既存の同周期任務については、各設定の右側にある「全デイリー任務に反映」「全クォータリー任務に反映」を押すと**OFFの任務も含めて**一括更新します。個別に指定していた曜日や実施月も上書きするため、その後に必要な任務だけ個別に調整してください。一括反映ボタンは任務の実施ON/OFFを変更しません。

### 一時保存した条件の比較

例：「案A＝デイリー週7日・クォータリー期首」「案B＝デイリー週3日・クォータリー期末」を比較する場合：

1. 任務のON/OFFや報酬を設定し、「条件の一時保存・比較」で保存名を入力して「現在の条件を保存」を押します。
2. デイリーやクォータリーの設定を変更します。**条件Bを保存する必要はありません**。比較先に「現在の設定」を選べば比較できます。
3. Bも保存したい場合には、名前を付けて再度「現在の条件を保存」を押します。
4. 「条件A（基準）」「条件B（比較先）」から、現在の設定や保存済みの条件を任意に2つ選びます。
5. 年間・月間の資材獲得数、**B − A の差分**、12か月の月別差分、設定が異なる任務の一覧を確認できます。

最大8件まで一時保持できます。保存済みの条件は各行の「削除」で消去できます。過去の案を編集の起点にする場合は「選択した条件Aを編集に復元」を押します（編集中の設定は上書きされるので確認ダイアログが出ます）。

**保存場所**：比較条件はブラウザの `sessionStorage` に保持されます。同一タブのページ再読み込み中は維持されますが、**別タブとは共有されません**。ブラウザ終了後までの保存は保証しません。通常の編集中の任務データおよびデフォルト値は従来どおり `localStorage` に保存され、JSONエクスポートにも含まれます。**比較用の一時保存8件はJSONに含めません。**

**比較の前提**：どの条件も画面上部の「計算期間（今月から12か月間）」に揃えて比較します。「年平均（月）」または指定月の表示も画面上部の設定を共有します。条件ごとの前提任務とスケジュールから獲得量を再計算するため、単純な設定値の差し引きではありません。獲得量は**グロス**で、任務達成に要した改修・開発資材の消費量は引きません。

### v2設定との互換性

v4はv2・v3と同じ `localStorage` の保存キーを引き継ぎます。既存v2のデータがあれば、登録任務や実施曜日、選択報酬などはそのままで、デフォルト値だけ「週7日」「四半期1か月目」を追加します。任務データの初期値は58件のままで、v2の未網羅箇所を増補したものではありません。

## 初期データ

初期登録58任務（デイリー22、ウィークリー18、マンスリー7、クォータリー10、イヤーリー1）。**全定期任務の網羅データではありません。** 基本4資源は58件に補完しましたが、選択報酬・装備・各種アイテムは確認できたものに限り登録しています。任務間の前提関係は2026年11月時点で確認できた**22の下流任務**に付与しています。出典のある関係に限定し、未確認の前提を推測で追加していません。

- デイリー出撃の連鎖（敵艦隊を撃破→敵艦隊主力→敵補給艦→南西→潜水艦など）
- ウィークリー（あ号→ろ号、い号→海上護衛→東方→中枢→南方、ろ号→海上輸送路など）
- 月次（ろ号→水雷戦隊・空母機動部隊、第五戦隊→海上護衛強化月間、空母機動部隊→水上反撃）
- 週次「装備の改修集中強化」は、デイリー「続：装備の改修強化」とウィークリー「大規模演習」の**両方**を前提に設定

### 前提条件の扱い

`prerequisites: ["ID1","ID2"]` は **AND 条件**です。前提任務を選択していないと下流はONにできません。既にONの下流で上流をOFFにすると、連鎖的にOFFになります。ツリーに循環が生じる編集は拒否します。

実施回数を見積もる場合、同周期・上位周期に対する前提条件を満たす期間のみ下流を計上します。例：あ号を「月初の1週」、ろ号を「毎週」にしても、ろ号は月初側の1週のみです。あ号が「月末の1週」でろ号が「月初の1週」なら、その月のろ号は0回です。

ただし**任務の正確な出現フラグの解除順、日付を跨ぐタイミング、ゲーム中の遂行順序まで再現するシミュレータではありません**。異なる周期をまたぐ前提は、共通のリセット期間内に少なくとも1回上流を実施するという近似です。達成率による補正は行いません。

**未登録の単発任務などの前提条件は計算上のロック対象外**です。一部の任務には「未管理の前提」として注記しています。完全な任務ツリーを作るには追加マスターが必要です。

## 日付と集計

- デイリー：選んだ曜日の実際の日付を対象年で列挙します。「週3日」は単純な30×3/7ではなく、指定した曜日がその月に何回あるかで計算します。
- ウィークリー：月曜日を各週の開始日とし、対象月に含まれる月曜日をカウントします。毎週はその月の月曜日が4回でも5回でも全部実施します。「月2週・月末側」はその月の最後の月曜日2回を選びます。
- マンスリー：毎月1回。
- クォータリー：3〜5月、6〜8月、9〜11月、12〜2月の各期で、任務別に設定した1か月だけ計上します。
- イヤーリー：各任務の`startMonth`から翌年の開始月直前までを1サイクルとします。`executionMonth`に設定した月に1回計上します。開始月より前の月を選んだ場合は前年開始サイクルに対する消化とみなします。実装年より前の可用性までは追跡しません。
- 年平均月間：暦年内の獲得合計÷12。あくまで**獲得量（グロス）**です。

## JSONフィールド

```json
{
  "id": "W-040",
  "name": "装備の改修集中強化",
  "period": "W",
  "active": true,
    "prerequisites": ["D-020", "W-033"],
  "weeklyWeeksPerMonth": "all",
  "weeklyPlacement": "first",
  "rewards": {"ネジ": 3},
  "choiceGroups": [
    {"name":"選択報酬1", "selected":0,
      "options":[
        {"label":"ネジ×2", "rewards":{"ネジ":2}},
        {"label":"釘×6", "rewards":{"釘":6}}
      ]
    }
  ]
}
```

- 共通：`prerequisites`は先行任務のID配列。`untrackedPrerequisites`は自動判定できない単発前提などのラベル。
- 日次：`dailyWeekdays`は曜日番号の配列（日0、月1、…、土6）。
- 週次：`weeklyWeeksPerMonth`は`"all"`または0〜5。`weeklyPlacement`は`"first"`または`"last"`。
- 季節：`quarterOffset`は0（期首）・1（2か月目）・2（期末）。
- 年次：`startMonth`は年次任務の更新月、`executionMonth`は消化月。
- 任務編集では循環する前提条件、存在しないID、無効な周期設定は拒否します。

## 既知の限界

- 初期収録の報酬・任務・依存条件は一部に留まります。任務の正式名称、報酬、更新状況はゲーム・攻略Wikiで別途確認してください。
- 不定期任務・日付限定任務・特殊な出現条件・改修や開発によるネジ・釘の**消費**は未計算。
- 前提任務と下流任務の消化日順を完全に計算するわけではないため、ゲーム実態と差が出る場合があります。
- 自動保存はブラウザのローカルストレージです。場所を変えて開くと保存情報が共有されない場合があるため、JSONエクスポートを推奨します。
